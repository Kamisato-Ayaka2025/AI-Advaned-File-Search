# 01 · QQ NT → Markdown

> 实测版本：QQ NT **9.9.33-52230**（Windows x64）。上游脚本在 9.9.32-51246 亦验证可用。
> 相关脚本：[`ntqq_export_md.py`](./ntqq_export_md.py)

---

## 1. 数据定位

```
C:\Users\<user>\Documents\Tencent Files\<UIN>\nt_qq\
├── nt_db\                 ← 全部加密库
│   ├── nt_msg.db          ← 私聊 + 群聊消息（主库）
│   ├── profile_info.db    ← 好友资料（昵称）
│   ├── group_info.db      ← 群列表、群成员、群名片
│   ├── emoji.db / files_in_chat.db / ...
│   └── *.db-wal, *.db-shm
└── nt_data\
    ├── Pic\<yyyy-mm>\Ori\<md5>.<ext>      ← 原图缓存
    ├── Pic\<yyyy-mm>\Thumb\<md5>_128.jpg  ← 缩略图
    └── File\
```

要点：

- `Tencent Files` 可被客户端改到其他盘，不能硬编码。
- 一个目录下可能有多份 `<UIN>`，按账号分别处理。
- 客户端运行时会持有主库与 WAL 句柄，**先复制再解密**。

---

## 2. 容器格式

所有 NTQQ 库共用同一容器（实测 21 个库全部成立）：

```
0x000  "SQLite header 3\0"     ← 伪魔数（真 SQLite 是 "SQLite format 3\0"）
0x010  伪头部字段（被写乱，普通 SQLite 打不开）
0x020  "QQ_NT DB"              ← 标记
0x02A  protobuf 元数据
       ├ field 2 : 128 字节 ASCII hex
       ├ field 3 : "1.1.0.1"      ← codec 版本
       ├ field 4 : "HMAC_SHA1"
       └ field 5 : varint
0x400  加密页起点（每页 4096）
```

**不变量**：`(文件长度 − 1024) % 4096 == 0`。不成立说明头部或页大小变了，应立即失败。
建议在代码里显式校验（`ntqq_export_md.py` 已实现）。

解密参数（剥掉前 1024 字节后）：

| 参数 | 值 |
| --- | --- |
| `cipher_page_size` | 4096（必须在 `PRAGMA key` 之前设置） |
| `kdf_iter` | 4000 |
| `cipher_hmac_algorithm` | `HMAC_SHA1`（2024-12 后上游记录改为 SHA512） |
| `cipher_kdf_algorithm` | `PBKDF2_HMAC_SHA512` |

> 实践建议：把 `(iter, hmac, kdf)` 做成候选列表轮询，避免死记某一版参数。

## 3. 密钥

- 形态：**16 字符**随机串，按账号 + 机器生成，不能跨机复用，也不能从库文件推导。
- 位置：只在客户端运行时存在于进程内存。

### 3.1 取密钥（官方脚本）

使用 [`QQBackup/qq-win-db-key`](https://github.com/QQBackup/qq-win-db-key) 的
`scripts/windows/ntqq/windows_ntqq_get_key.ps1`。

```powershell
# 1) 先做静态分析，确认当前版本还能定位到函数（不动 QQ）
powershell -ExecutionPolicy Bypass -File .\windows_ntqq_get_key.ps1 -NoDebugForKey -Verbose

# 2) 完全退出 QQ（单实例机制会让新进程秒退）
taskkill /F /IM QQ.exe /T

# 3) 动态取 key：脚本会拉起 QQ，在弹出的窗口完成登录
powershell -ExecutionPolicy Bypass -File .\windows_ntqq_get_key.ps1 -Verbose

# 4) 输出 "加密密钥: XXXXXXXXXXXXXXXX" 即成功
```

原理（脚本内部）：

1. 在 `versions\<ver>\resources\app\wrapper.node` 里搜字符串
   `nt_sqlite3_key_v2: db=%p zDb=%s`；
2. 找引用它的 `lea` 指令，再用 `.pdata` 异常目录反查所属函数 RVA；
3. `CreateProcess(QQ.exe, DEBUG_ONLY_THIS_PROCESS)`，在函数 RVA 下软件断点；
4. 登录触发建库 → 从寄存器 `R8` 读 `pKey`（16 字符）；
5. 脚本结束会终结它拉起的 QQ 进程。

### 3.2 硬约束

| 约束 | 原因 |
| --- | --- |
| 必须先关闭 QQ | 单实例互斥，新进程会直接退出 |
| 必须完成一次登录 | 不登录不会打开 `nt_msg.db`，断点不触发 |
| 会打断当前会话 | 脚本结束会 kill 掉它拉起的 QQ，需重新登录 |
| 版本敏感 | 函数 RVA 随版本变化，脚本靠字符串+交叉引用动态推导，大改版可能失效 |

> 产品化视角：这一步必须做成**显式授权**动作，不能静默执行。

## 4. 解密

```text
1. 复制 nt_msg.db / -wal / -shm 到临时目录（快照）
2. 主库去掉前 1024 字节 → clear.db
3. 把 -wal / -shm 改成 clear.db-wal / clear.db-shm（否则丢最新消息）
4. SQLCipher 打开，校验能读 sqlite_master
5. sqlcipher_export() 导出明文库
```

失败特征：

| 现象 | 原因 |
| --- | --- |
| `file is not a database` | 没剥头，或用了普通 SQLite |
| `hmac check failed for pgno=1` | 密钥/参数/页大小错 |
| 能开库但表为空 | WAL 没带上，或剥头偏移错 |

## 5. 消息表

`c2c_msg_table`（私聊）与 `group_msg_table`（群聊）列结构相同：

| 列 | 含义 | 备注 |
| --- | --- | --- |
| `[40001]` | msgId | 雪花 ID，**高位不是消息时间** |
| `[40003]` | msgType | 含系统消息码 |
| `[40011]` | msgSeq | 会话内序号 |
| `[40020]` | 发送者 uid | `u_xxx` |
| `[40021]` | 会话标识 | 私聊=对方 uid；群聊=群号 |
| `[40033]` | 发送者 QQ 号 | |
| `[40050]` | 消息时间戳 | 秒级，可能为 0 |
| `[40058]` | 当天 0 点时间戳 | 可能为 -1 |
| `[40090]` | 群名缓存 | **不可靠**，可能写入广告文本 |
| `[40093]` | 发送者群昵称 | 常为空 |
| `[40800]` | 消息体 | protobuf，可能为 NULL |

---

## 6. 消息体（Element）

`[40800]` 是 wrapper，内部为**扁平化**元素列表：`45002` 开启新元素并给出类型，
后续同段字段归属该元素。

| `45002` | 类型 | 主要字段 |
| --- | --- | --- |
| 1 | 文本 | `45101` 正文 |
| 2 | 图片 | `45402` 文件名、`45406`/`45408` 摘要、`45802` 服务端参数 |
| 3 | 文件 | `45402` 文件名、`45403` 本地路径（`::NTOSFull::` 前缀）、`45405` 大小 |
| 5 | 视频 | `45402`/`45422` 文件名 |
| 6 | 表情 | `47601` ID、`47602` 名称 |
| 7 | 引用 | `47423` 内嵌 protobuf，field 9 = 被引文本 |
| 8 | 灰条/系统 | `45003` 子类型、`48214` HTML/XML、`485xx` 结构化字段 |
| 10 | 卡片 | `47901` JSON |
| 11 | 商城表情 | `80900` 名称 |
| 16 | XML | `48602` XML，取 `<title>` |

---

## 7. 时间戳规则

1. 首选 `[40050]`；
2. 为空用 `[40058]`；
3. **`msgId >> 32` 不可用**：实测它是批量同步时间，2204 条样本中 1497 条偏差 > 2 分钟，
   P95 偏差 200 天。用它兜底会把消息放错日期。
4. 两者都不可用时，按会话内 msgId 顺序**继承最近一条已知时间**（脚本已实现）。

## 8. 昵称与群名

| 来源 | 用途 | 字段 |
| --- | --- | --- |
| `nt_uid_mapping_table` | uid → QQ 号 | `[48902]` → `[1002]` |
| `profile_info_v6` | 好友昵称 | `[1000]` uid、`[1002]` uin、`[20002]` 昵称 |
| `group_list` | **权威群名** | `[60001]` 群号、`[60007]` 群名 |
| `group_member3` | 群名片 | `[60001]`、`[1000]`、`[64003]` 名片、`[20002]` 昵称 |

> 群名优先取 `group_list`，`[40090]` 只作兜底。实测 `[40090]` 出现过广告文案。

---

## 9. 媒体关联

- 图片缓存：`nt_data/Pic/<yyyy-mm>/Ori/<md5>.<ext>`，缩略图在 `Thumb/`。
- 用元素的 `45406`/`45408` 十六进制摘要匹配文件名主干。
- **只能命中仍在本机的缓存**：本次 179 个图片元素中 49 条可链接，其余标注“未缓存”，不伪造链接。

## 10. 导出

```bash
export NTQQ_DB_KEY='<16 字符>'
python ntqq_export_md.py --nt-db "<...>/nt_qq/nt_db" --out ./qq --my-uin <UIN>
```

参数：`--nt-db` 加密库目录、`--out` 输出目录、`--my-uin` 自己的 QQ 号（渲染为“我”）、
`--pic-root` 可选（图片缓存根，默认 `../nt_data/Pic`）。

输出遵循 [`03-markdown-contract.md`](./03-markdown-contract.md)。

## 12. 限制

- 解析依赖“字段号即语义”，属逆向结论。客户端调整编号时可能**不报错但产出错乱内容**，
  因此脚本内置抽样断言，失败应判为不支持而不是输出半成品。
- 未缓存的历史图片/视频无法补。
- 语音、合并转发未处理。
