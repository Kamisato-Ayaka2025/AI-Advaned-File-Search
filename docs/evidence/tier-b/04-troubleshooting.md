# 04 · 故障排查与版本敏感性

汇总 QQ / 微信两条链路的失效模式、环境坑与处置。遇到问题先按“现象”定位小节。

---

## 1. 通用环境

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64 |
| Python | 3.10+ |
| 依赖 | `sqlcipher3-binary`、`zstandard`、`cryptography`；微信 WXGF 需要 `ffmpeg` |
| 权限 | 普通用户即可（读同用户进程内存不需要管理员） |
| 客户端 | 必须已安装并**登录过至少一次**，且运行时才持有密钥 |

常见坑：

- **客户端运行时占用数据库**：先复制 `db + -wal + -shm` 再做离线解密，不要直接解活库。
- **`ffmpeg` 不在 PATH**：WXGF 转码会全部失败（`wxgf_fail`），其余流程不受影响。
- **路径含中文/空格**：脚本全部按 UTF-8 处理，但 shell 里要正确加引号。

## 2. QQ

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 脚本一直等不到断点 | QQ 没关干净（单实例） | `taskkill /F /IM QQ.exe /T` 后重跑 |
| 静态分析找不到函数 RVA | `wrapper.node` 大版本变动 | 升级 QQBackup 脚本；或改用其他取密钥方案 |
| `file is not a database` | 没剥 1024 字节头 / 用了普通 SQLite | 用 SQLCipher，先剥头 |
| `hmac check failed for pgno=1` | 密钥或参数错 | 轮询 `(iter, hmac, kdf)` 组合 |
| 能开库但表为空 | WAL 没带上 | 复制 `-wal/-shm` 并同名 |
| 消息日期离谱 | 用了 `msgId >> 32` 兜底 | 改用 `40050 → 40058 → 相邻继承` |
| 群名是广告文案 | `[40090]` 不可靠 | 优先 `group_list[60007]` |

## 3. 微信

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `Weixin.exe not running` | 客户端没开 | 启动并登录后重试 |
| `verified = 0/N` | **账号目录选错**（最常见） | 用能解开库的密钥反证账号；不要按 mtime 选目录 |
| `needles = 0` / `nodes = 0` | 结构偏移漂移 | 重采 `Config.Cipher` 节点偏移与掩码 |
| 候选很多但全部验不过 | 掩码或偏移错 | 用“解一段已知 .dat / 库页 1”的判据重新校准 |
| `integrity_check` 报 `SQL logic error` | FTS 私有分词器缺失 | 脚本已容错，标 `n/a(fts)`，影子表仍导出 |
| 图片解码全是随机字节 | 用错了 AES key（消息 `aeskey` 不是它） | 用 `wechat4_find_image_key.py` 从内存取 16 字节 ASCII key |
| 取不到图片密钥 | **密钥是会话级的**：客户端重启后若没打开过图片，内存里没有 | 在微信里点开 2–3 张图片，再重跑 |
| 图片尾部花屏 | XOR key 不是 0xAC | 用 JPEG EOI（`FFD9`）反推：末字节 ^ `0xD9` |
| WXGF 转码失败 | 码流里没有起始码 | 记录为 `wxgf_no_startcode`，不硬凑 |
| 链接全部断掉 | 相对路径按导出根算了 | 以“会话文件所在目录”为基准 |

## 4. 版本敏感性

| 组件 | 随版本变化的部分 | 回归方式 |
| --- | --- | --- |
| QQ `wrapper.node` | 取密钥函数 RVA | 跑 `-NoDebugForKey` 看是否仍能找到 |
| QQ 容器 | 头部长度 / 页大小 | 校验 `(size-1024) % 4096 == 0` |
| 微信 `Config.Cipher` | 节点 `+0x28`、对象 `+0x88`、24 字节掩码 | 看 `nodes/blobs/verified` 三级计数 |
| 微信图片 | V2 头字段、AES key 位置、XOR key | 先解一个样本看能否出现图片魔数 |

> 升级后**必须**重跑一次“取钥成功率 + 抽样行数”，不要假设上次结论仍成立。

## 5. 工程坑（踩过的）

1. **`.gitignore` 的 `/exports/`**：导出目录被排除，提交需换目录名或 `-f`。
2. **`.gitignore` 的 `private/`** 是全局规则（任意层级），上传含 `private/` 的导出必须
   `git add -f`，否则私聊全部静默丢失。
3. **`cp -r src dst`**：`dst` 已存在时会嵌套成 `dst/src`，上传前务必校验目录层级。
4. **`ALL.md` 留在导入目录**：会被当成单会话解析失败，必须外置。
5. **媒体映射表存相对路径**：会被解析成相对当前工作目录，导致全部断链，应存绝对路径。
6. **aimem 不走语义**：`stats` 里 `embedder: hash` 表示当前是哈希向量，
   检索质量不代表语义能力；接真模型前不要用它评估“找得到”。

## 6. 性能基线

| 步骤 | 本机耗时 |
| --- | ---: |
| 微信取密钥 | 2.0 s |
| 微信解密 22 库（~81 MB） | 12.4 s |
| 微信导出 19 159 条 | 0.68 s |
| 微信图片 505 张（含 312 次 ffmpeg） | 55.6 s |
| QQ 解密 + 导出 2 234 条 | < 5 s |
| 全量重跑（不含 QQ 登录） | ~1.5 min |

## 7. 隐私与合规

- 密钥只放环境变量或临时文件，用完删除；**禁止提交**。
- 运行库、导出结果、图片目录都被 `.gitignore` 覆盖（`*.db`、`*.db-*`）。
- 读进程内存属敏感操作：产品化时必须做成显式、可解释、可拒绝的动作。
- 仅处理本机、本账号、本人授权的数据。
