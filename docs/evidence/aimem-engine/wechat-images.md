# 微信图片导出与 OCR 记录

> 仅记录聚合指标与工程结论；仓库不包含图片、聊天文本或数据库。

## 1. 导出

| 项 | 值 |
|---|---:|
| 图片消息 | 879 |
| 图片链接 | 521 |
| 断链 | 0 |
| 解码成功 | 505（37 jpg / 156 png / 312 wxgf） |
| 无本地缓存 | 349 |
| 路径失效 | 9 |

- 微信 4.0 图片为 V2 加密 `.dat`；从客户端进程内存取得 16 字节密钥后按 AES 解密。
- wxgf 为 HEVC 封装，用 ffmpeg 转码。
- Markdown 契约：`![图片](<../images/<md5>.png>)`，从 `group|private/*.md` 解析正确。

## 2. OCR

- 引擎：RapidOCR（CPU/ONNX）。
- 全量 505 张：**377 张有文字（75%）**，128 张无文字。
- 平均约 0.9s/张（缩放至 1600px）。
- 388 条消息带 `[图片文字]` caption；**377/879 图片消息可搜（43%）**。

## 3. 隔离测试

从 caption 中提取「只存在于图片、不存在于任何文本消息」的 12 个词：

```
post-OCR image hit rate: 12/12 = 100%
pre-OCR  image hit rate: 0/12  = 0%
```

## 4. 工程问题

- 一张 1.3 亿像素图片导致 OOM。
- 修复：缩放至最长边 1600px、跳过 >40MP、caption 持久化缓存、分批处理。

## 5. 局限

- 表格类截图 OCR 文本碎片化，需要版面重建或 VLM。
- 128 张无文字图片需要 VLM 描述。
- 349 张无本地缓存，需在客户端重新下载。

## 6. 接入建议

上游导出器增加 `--ocr`（可选 `--vlm`）：

```markdown
> ![图片](<../images/xxx.png>)
> [图片文字] ...
```

有文字图片用 OCR；表格与无文字图片优先 VLM。caption 与消息同一条 `Unit`。

> 注意：当前产品 `Plan.md` 明确排除 OCR；本记录为研究证据，不改变产品范围。
